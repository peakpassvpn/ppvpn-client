# 真机 QA 清单

CI 和虚拟机、容器覆盖不到的项目，发版前在真机上逐项过一遍。每项记录平台、系统版本、
app 版本与 build、core 版本和结果；失败时附上日志（位置见 [../README.md](../README.md)）。

## macOS

Apple 芯片和 Intel 各一台更好。

- [ ] 首次打开：系统拦截未识别的开发者，经「系统设置 → 隐私与安全性 → 仍要打开」后能正常启动。
- [ ] 应用内更新（Sparkle）：更新安装后直接打开，不需要再次放行。
- [ ] 换 Wi‑Fi 后直连域名仍能解析（core 自己读取物理网卡的 DNS）。
- [ ] Wi‑Fi 与有线之间切换后连接恢复，直连与代理都可用。
- [ ] 同时开着另一个 VPN 时，core 日志里 `msg="local dns servers"` 的 interface 是物理网卡，
      不是对方的虚拟网卡。
- [ ] 兼容模式（系统代理）：与其他会设置系统代理或系统 DNS 的软件共存时，开启和关闭都不残留、
      不覆盖对方的设置。

## Windows

- [ ] 下载并运行安装包：SmartScreen 与 UAC 的提示和发布者显示符合预期（未做受信任签名时发布者为「未知」，
      SmartScreen 选「仍要运行」后能安装）。
- [ ] 应用内更新（WinSparkle）：更新过程中的 UAC 提示正常，更新后版本正确、连接可用。
- [ ] 精确式触控板平移时，日志页的「跟随」状态正确。

## Linux

Ubuntu Desktop（NetworkManager）真机；没有 udev 的容器里测不了网卡事件。

- [ ] 增强模式已连接时把物理网卡 down 再 up：core 的策略路由规则（`ip rule`）仍在或被立即补回，
      期间没有流量绕过隧道泄漏。

## 所有平台

- [ ] 整机 failover：当前节点的入口整体不可用时切换到其他入口，连接恢复；原入口恢复后行为正常。

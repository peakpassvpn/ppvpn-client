# 0.6.0 发行说明

0.6.0 是 Rust 版的第一个对外版本，版本号接着 Go 版走（Go 的最后一版是 0.5.21）。引擎 `ppvpn-core`、账号 `ppvpn-account`、命令行 `ppvpn`、桌面客户端和特权服务都是 0.6.0。Go 0.5.21 的 tag 和 Release 文件保留，需要时仍可下载。

## 主要变化

- **内核换成 Rust。** 网络引擎改为 Rust 库 `ppvpn-core`，内嵌 Sail 0.18.0，取代 Go 内核和 sing-box。引擎不再是单独的进程，而是在宿主进程里运行：
  - 桌面端的标准模式（本地代理）在应用进程里；
  - 增强模式（TUN）在特权服务进程里；
  - 命令行在它自己的进程里。
- **桌面端，三个平台：**
  - macOS：SwiftUI 应用，arm64 和 x64 两个 DMG，经 Sparkle 自动更新；
  - Windows：WinUI 3 应用，x64 NSIS 安装包，经 WinSparkle 自动更新；
  - Linux：GTK 4 应用，x64 的 deb 和 rpm，另有 apt、dnf 仓库。
- **命令行 `ppvpn`。** 用浏览器的设备码登录，凭据只存在系统密钥库里：macOS 是钥匙串，Linux 是 Secret Service。没有可用的密钥库时登录直接失败，不会把凭据明文写到文件里。登录后运行一个标准实例，提供带认证的本地 HTTP/SOCKS5 代理。命令行不建 TUN，也不改系统的网络设置。

## 与 0.5.21 的行为差异

以下是用户或运维能感知到的变化。完整的逐条对照见 [Rust 版行为对照](../rust-parity.md)，接口语义见 [宿主接入](../host-integration.md)。

**切换配置**
- 运行中换 Profile、切换路由模式或选择节点时，在同一个实例里原地 reload，不再有"旧内核排空"：
  - 不发 `KernelDrained`，`draining_kernels` 恒为 0；
  - 已有连接留在原来的出站上继续运行。
- 监听的增、删、改也原地完成，只有 TUN 本身变了才完整重启（这时所有连接都会断开）。0.5.21 对任何监听变化都整体重启。
- 新 Profile 删掉某个节点时，经过这个节点的连接在切换时被关掉；新 Profile 加的 reject 规则现在会拒绝的已开连接也被关掉（UDP 会话按它的第一个目的地址判断）。`KernelSwitched` 的 `closed_connections`、`kept_connections` 给出关掉和留下的数量。

**错误码更细**

0.5.21 的这些情况都报 `CORE_OPERATION_FAILED`，现在报更具体的码：

| 情况 | 现在的错误码 |
|---|---|
| 未应用 Profile 就 start | `PROFILE_NOT_APPLIED` |
| select-node 选一个不存在的节点 | `NODE_NOT_FOUND`（field=`node_id`） |
| 空 Profile | `PROFILE_REQUIRED` |
| 不是合法 JSON，或字段类型不对 | `PROFILE_MALFORMED`，消息里不带原值 |

另外，apply 时 `selection.default_node_id` 指向不存在的节点会报 `DEFAULT_NODE_NOT_FOUND`，0.5.21 会接受。

**UDP**

规则把 UDP 送到 `capabilities.udp=false` 的节点或入口时，直接拒绝，不经过这个节点，也不改走别处。0.5.21 不检查这个字段，照常经该节点发出。

**节点健康**

多入口节点的成员拨号失败时，同样立即判为不健康。不同的是，连续失败计数只加 1；0.5.21 直接把计数抬到阈值。

**网络变化**

默认网卡变化在 2 秒内上报，变化后的第一次 DNS 查询就用新网络。0.5.21 在网络事件密集时可能晚几秒才跟上。

**日志**
- info（默认）级别不出现连接的目的地址或域名。Sail 自己的日志在 info 下只记 warn 及以上。
- debug 下的 `outbound failed` 行没有 `network` 和 `ms`，`error` 是 I/O 错误的类别，另有 `count`。
- `default interface` 行没有 `mtu`。

## 已知限制

- **不处理企业 VPN 的 split DNS。** 增强模式下，直连的域名一律用物理网络的 DNS，与 0.5.21 相同。
- **macOS、Windows 只检测、不自愈。** 增强模式下，别的程序（通常是另一个 VPN）改动了 TUN 的路由或地址时，`status.tun_routing` 变为 `broken`，状态进入 `Degraded`，实例继续运行，但部分流量可能绕过 TUN，直到下一次连接。桌面端会自动重连，10 分钟内最多 3 次，之后提示用户。Linux 有路由守护，能补回就补回，补不回才断开。
- **Linux 增强模式下部分入站连接的回包进隧道。** 局域网用私有地址时，局域网主机连进本机（例如 SSH）没有问题。但局域网用公网地址段、经全局 IPv6 连进来，或者从公网连进本机时，回包仍会进入隧道，连接无法建立。计划用连接标记解决（#320）。
- **Profile 过期不提示。** 越过 `expires_at` 后还不会进入 `Degraded{ProfileExpired}`。
- **移动端未提供。** 还没有 iOS 和 Android 的版本。

## 升级注意

- **设备码登录只认新的授权页地址。** 桌面端和命令行只接受后端返回的 `/dashboard/device/authorize`。仍然返回旧地址 `/dashboard/cli/authorize` 的后端，登录会被拒绝（`AuthUntrustedResponse`）。请先升级后端。
- **Linux 内存。** 在 glibc 上，`MALLOC_ARENA_MAX=2` 已经内置：
  - 命令行启动时自己设定，环境里显式设置的值优先；
  - 特权服务的 systemd 单元带上了这个环境变量；
  - 桌面应用的启动项和开机自启项也带上了。

  自行承载引擎的宿主仍应自己设置，见 [宿主接入](../host-integration.md) 第 1 节。
- **自行承载引擎的宿主。** 接口以 [宿主接入](../host-integration.md) 为准。在多线程 tokio 运行时里调用 `Engine::new` 时，实例跑在这个运行时上，这个运行时要一直活到 `shutdown` 返回。

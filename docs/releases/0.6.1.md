# 0.6.1 发行说明

0.6.1 是 0.6.0 之后的修复版。引擎 `ppvpn-core`、账号 `ppvpn-account`、命令行 `ppvpn`、桌面客户端和特权服务都是 0.6.1。

## 主要变化

- **刚开通的订阅显示"节点准备中"。** 后端对订阅已生效、节点还没发布的情况返回 `PROXY_NODES_NOT_READY`。
  - 桌面端三个平台显示"节点准备中 / Setting Up Servers"，不再显示"没有订阅"和购买入口。
  - 客户端自己重新拉取 Profile：30 秒后一次，60 秒后一次，之后每 2 分钟一次，节点一到就直接可用。卡片上的"刷新"只是让它马上再拉一次。
  - 命令行 `ppvpn start` 的错误信息会说明是哪种订阅问题，节点没准备好时提示稍后再试。退出码不变，`--json` 的 `code` 原样给出后端的码。
  - 命令行下载 Profile 被后端拒绝（4xx）时，错误信息里带上后端给的说明（例如"no active subscription"），便于看出是哪种情况。退出码和 `code` 不变。
  - 没有订阅（`SUBSCRIPTION_REQUIRED`）、订阅过期、团队停用的显示不变。后端还没有上线这两个新码时，客户端照旧按"没有订阅"处理。
- **可用性探测在个别节点上误报谷歌不可达的问题已修复（#342）。** 在一个节点出口上，谷歌前端（`www.gstatic.com`、`www.google.com`、`connectivitycheck.gstatic.com`）会在请求发出后直接关闭只走 HTTP/1.1 的探测连接，探测报 `CONNECTION_CLOSED`，而节点本身可用。现在探测的 ALPN 同时提供 `h2` 和 `http/1.1`，协商到 `h2` 时用 HTTP/2 发请求；探测发出的 ClientHello 也改成 Chrome 的。规则集下载不变。
- **可用性探测的失败码按失败的那一步区分。** 原来拨号、TLS、读响应失败都报 `PROXY_REQUEST_FAILED`，现在分别报：
  - `CONNECT_FAILED`、`TLS_HANDSHAKE_FAILED`、`TLS_CERTIFICATE_INVALID`、`CONNECTION_CLOSED`、`RESPONSE_INVALID`、`REDIRECT_LOOP`；
  - 不支持的 scheme 报 `TARGET_INVALID`；
  - `PROXY_REQUEST_FAILED` 只剩"节点出站本身不可用"一种情况。

  探测的读写失败会在 info 级别记一行日志，不带目标地址。桌面端的显示不变：拨号失败仍显示"不可达"，其余的显示"探测失败"。自行承载引擎的宿主应把不认识的码当作一般的探测失败，见 [宿主接入](../host-integration.md)。
- **Sail 升到 0.19.2。**

## 自动更新

从 0.6.0 起，macOS 和 Windows 的更新包放在更新站点 `pkg.peakpassvpn.com` 上（经 Cloudflare 缓存），不再从 GitHub Release 下载。在一些网络下，从 GitHub 下载太慢，更新会失败。这项改动已经对 0.6.0 的更新源生效。更新包仍由 EdDSA 签名校验；GitHub Release 里的文件照旧可以下载。

## 升级注意

- **macOS：升级后第一次用增强模式连接时，会要一次管理员密码。** 0.6.1 的特权服务和 0.6.0 的不同，连接前客户端会替换它，提示和第一次安装时一样。在这个提示里点取消，这次仍用旧服务连接；重启应用后会再问。只用标准模式时不会提示。
- Windows 的服务由安装程序替换，Linux 的由软件包替换，都不需要额外操作。

## 已知限制

- **macOS 自动更新后约 1 分钟收不到推送。** 应用被替换的那一刻，系统按启动约束结束旧的推送助手（PPVPN Agent），可能留下一份"PPVPN Agent"崩溃报告；新版本启动后会重新注册，约 1 分钟后恢复。连接不受影响，也不需要任何操作。
- 其余与 [0.6.0](0.6.0.md#已知限制) 相同，只有"刚开通订阅时可能显示没有订阅"已经解决。

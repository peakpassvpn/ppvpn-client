Apple native entry and transport integration status (2026-11-07)

Implemented in source
  ci-build.sh explicitly concatenates ApplePushState.swift, ApplePush.swift,
  ApplePushBridge.swift into the generated AppDelegate build source, preserving
  @preconcurrency imports. The native launch hook starts the strong receiver
  before implicit Flutter initialization. Token/failure/background callbacks
  forward to that receiver; callbacks complete once and background work has
  a 25s deadline. Copied standalone Runner sources are removed after inclusion
  so generated project styles cannot accidentally compile duplicates.

  IOSApplePushBridge attaches its MethodChannel at PPVPNPlugin registration.
  Cold notices remain in the bounded native mailbox until the stable account
  is restored. Dart AppState follows account_id, not account_name. Notices
  perform authorized inbox lookup and never use notification body/URL for UI.
  Explicit sign-out waits for the serialized unregister effect before Rust
  revokes the bearer. Restoring/replacement owners fence prior delivery.

Not completed
  ApplePush.register/unregister transport hooks intentionally have no default
  HTTP implementation. They return no successful native acknowledgement until
  the backend owner delivers actual OpenAPI/SDK and precise source commit.
  apple-push-contract.json identifies the actual handoff and required guards;
  the previous speculative endpoints/version fields have been superseded.
  No token-only legacy endpoint fallback. No rollout flag enabled.

Packaging and acceptance
  Formal API origin is read from repository PPVPN_API_BASE (the release.md
  authority), never inferred from its hostname. A diagnostic package built
  with api.example.invalid is not eligible for network acceptance.
  check-ios-apple-push.py validates an enabled signed package's actual aps
  entitlement, embedded provisioning profile, declared environment and topic.
  TestFlight requires production APNs. Sandbox receipt is not environment.
  Keep iOS package/App Group identities for a provisioned isolated test device;
  do not install over a live user VPN. Use build number0 for unsigned compile
  diagnostics; signed internal candidates require build group's unique number,
  app+extension profile equality and separate artifact directory/manifest.
  Do not upload a package before actual signed runtime acceptance.

macOS
  Existing agent remains. Receiver state is shared, but macOS native entry,
  authenticated transport, signed capability and actual foreground/background/
  terminated/cold tap/token rotation/logout/account-switch parity still need
  desktop-owner integration and verification before agent retirement.

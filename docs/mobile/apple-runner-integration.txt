Native and storage
  iOS ci-build concatenates shared ApplePushState + ApplePushInstallation,
  receiver and bridge into generated AppDelegate. Start the strong receiver
  at launch, attach at the implicit-engine registrar, forward OS token,
  registration failure and background callbacks. A native25s one-shot deadline
  bounds completion. UI still needs the signed actual environment/topic.
  Installation UUID/proof are separate from auth credential and Apple key.
  The proof store uses random32 bytes, app-only nonsynchronizing Keychain,
  app/topic/environment scope, AfterFirstUnlockThisDeviceOnly; macOS uses
  data-protection Keychain. Locked/denied/corrupt reads fail closed; they
  never rotate an existing proof. No disk-cached OS token is replayed.
  These storage calls were SDK-typechecked, not executed on a signed device.

Transport and ownership
  AppState supplies stable account_id to ApplePushTransport. Native effects
  also echo the Dart account transition's local clientEpoch; queued effects
  and late success cannot become a same-ID relogin's new request. Neither
  local epoch is sent as an HTTP version or substitute for real JWT sid.
  Authenticated HTTP stays in Rust; no bearer enters Swift/Dart. The account
  API allows only these Apple and authorized inbox operations, prevents URL/
  account injection, and strips backend failure detail/unknown error codes.
  Resolve gets current opaque binding once. Bind uses exact expected value,
  stable request_id/input, max3 transient attempts, no409 re-Resolve/rebind.
  Same current user is insufficient: bound_to_current_session must also be
  true to reuse a binding. Registration uses exact expected_registration_id.
  Native token rotation updates the same binding. If a previous token commit
  is uncertain, a bounded read-only Resolve can refresh registration CAS only
  within that exact active session/binding; it never rebinds a changed owner.
  Explicit logout invalidates
  local admission, drains serialized old-owner unregister, then Rust revokes
  auth. If timeout/response loss prevents close, backend session revocation
  is still the durable anti-revival fence; no success is fabricated.
  GET delivery (or single message for a legacy hint) uses the current Bearer.
  A failed delivery never falls back to payload text, URL or another endpoint.
  Native input carries only delivery/account/message IDs. Typed authorized
  server messages use the existing category/link mapping. UI and Rust both
  fence stale owners/sessions. Foreground pulls bounded /messages/updates and
  reloads authorized inbox; notification body/URL never supplies UI content.

macOS native hooks delivered as an independent build helper
  The owned MainFlutterWindow prepares the strong singleton before creating
  Flutter, sets a weak window activation closure, and attaches its registrar
  after generated plugins. Activation waits for authenticated notice success
  and matching native clientEpoch, so late old-owner replies cannot show it.
  tools/apple/macos_push_hooks.py injects AppDelegate initialization, will-
  finish launch, OS token success/failure and remote notification callbacks
  into the actual Flutter template. Init prepares UN delegate ownership;
  launch registers once. Optional absent Flutter super callbacks are guarded.
  The helper upgrades push_config.py's old source block to all4 Apple native
  files in the existing MainFlutterWindow build unit, removes identical copied
  standalone sources, and fails without mutation on unknown hooks/templates,
  unmanaged duplicates or modified copies. Reapplying it is byte-identical.
  The receiver preserves the previous weak UN delegate for local notifications.
  OFF or missing capability never invokes system registration/delegate/permission
  boundaries. No hook initializes a forwarding Engine; existing Agent unchanged.

  Build-owner minimal call, AFTER runner copy and push_config.py sources:
    python3 "$root/tools/apple/macos_push_hooks.py" \
      --app-root "$root/apps/flutter" \
      --generated-root "$root/apps/flutter/macos"
  Run this last source inclusion helper before compiling. Do not subsequently
  replace its source block with the older push_config.py sources command, or
  separately add the four concatenated files to the Xcode source list.
  ci-build.sh call entry, profiles, entitlements and signing remain build-owned.

  Targeted checks (no app launch or system registration):
